# Unix Shell Emulator (VFS)

## 1. Общее описание

Эмулятор командной оболочки UNIX-подобной ОС с виртуальной файловой
системой (VFS). Реализован на Python с графическим интерфейсом на
Tkinter. Эмулятор повторяет поведение командной строки UNIX-подобных
систем: разбирает введённую строку на команду и аргументы, раскрывает
переменные окружения хоста, выполняет поддерживаемые команды и
сообщает об ошибках.

Виртуальная файловая система загружается из ZIP-архива **целиком в
память** (без распаковки на диск). Команды `ls`, `cd`, `head`, `tac`,
`wc`, `cp` работают с этой виртуальной ФС. Изменения (`cp`) хранятся
**только в памяти** и не записываются обратно в архив.

Работа выполняется поэтапно:

- [x] Этап 1. REPL — диалог с пользователем, парсер, заглушки команд.
- [x] Этап 2. Конфигурация — параметры командной строки, стартовый скрипт.
- [x] Этап 3. VFS — загрузка виртуальной файловой системы из ZIP-архива.
- [x] Этап 4. Основные команды — `head`, `tac`, `wc`.
- [x] Этап 5. Дополнительные команды — `cp`.

## 2. Функции и настройки

### Поддерживаемые команды

| Команда | Аргументы | Описание                                             |
|---------|-----------|------------------------------------------------------|
| `ls`    | до 1      | список файлов в директории VFS                       |
| `cd`    | до 1      | сменить текущую директорию в VFS                     |
| `head`  | 1         | первые 10 строк файла VFS                            |
| `tac`   | 1         | строки файла VFS в обратном порядке                  |
| `wc`    | 1         | число строк, слов и байт в файле VFS                 |
| `cp`    | 2         | копировать файл VFS (только в памяти)                |
| `exit`  | нет       | завершить работу эмулятора                           |

Без `--vfs` команды работают как заглушки (этап 1). С `--vfs` они
работают с виртуальной файловой системой.

### Семантика `cp`

- `cp <file> <newfile>` — копия под новым именем (родительская
  директория должна существовать).
- `cp <file> <dir>` — копия внутри существующей директории под
  исходным именем.
- Копирование директорий не поддерживается.
- Копия хранится в памяти; исходный zip не изменяется.

### Раскрытие переменных окружения

Команды поддерживают подстановку переменных окружения реальной ОС
через `os.path.expandvars`. Например, `$USERPROFILE` на Windows или
`$HOME` при заданной переменной.

### Параметры командной строки

| Параметр   | Описание                                        |
|------------|-------------------------------------------------|
| `--vfs`    | путь к физическому расположению VFS-архива      |
| `--script` | путь к стартовому скрипту эмулятора (`.emu`)    |
| `--no-gui` | выполнить стартовый скрипт в консоли без окна   |

При запуске эмулятор печатает отладочный вывод всех заданных
параметров:

```
[debug] vfs    = scripts\vfs\deep.zip
[debug] script = scripts\start_deep.emu
[debug] no_gui = False
```

### Обработка ошибок VFS

| Ошибка                                  | Когда возникает          |
|----------------------------------------|--------------------------|
| `Error: VFS file not found: <path>`    | файл архива не найден    |
| `Error: invalid VFS archive: <path>`   | файл не является ZIP     |

### Обработка ошибок команд

| Ошибка                                          | Когда возникает                   |
|-------------------------------------------------|-----------------------------------|
| `Error: unknown command: <name>`                | неизвестная команда               |
| `Error: <cmd>: invalid number of arguments`     | слишком много аргументов          |
| `Error: <cmd>: missing file operand`            | `head`/`tac`/`wc`/`cp` без аргумента |
| `Error: ls: no such file or directory: <path>`  | путь не существует                |
| `Error: cd: no such directory: <path>`          | директория не существует          |
| `Error: no such file: <path>`                   | файл не существует                |
| `Error: is a directory: <path>`                 | передан путь к директории         |
| `Error: no such directory: <path>`              | родитель `cp` не существует       |

## 3. Сборка и запуск тестов

### Требования

- Python 3.10+
- Tkinter (входит в стандартную поставку Python для Windows)

### Установка окружения

```cmd
python -m venv .venv
.venv\Scripts\activate
python -m pip install -U pytest
```

### Запуск эмулятора

```cmd
run.bat
```

или

```cmd
python -m src.main
```

### Запуск тестов

```cmd
python -m pytest
```

или с подробным выводом:

```cmd
python -m pytest -v
```

## 4. Примеры использования

### Запуск без параметров (интерактивный GUI)

```cmd
run.bat
```

### Запуск со стартовым скриптом (GUI + автопроигрывание)

```cmd
python -m src.main --vfs scripts\vfs\deep.zip ^
    --script scripts\start_deep.emu
```

Окно открывается, в нём автоматически проигрывается скрипт,
после чего можно продолжать вводить команды вручную.

### Запуск стартового скрипта в консоли

```cmd
python -m src.main --vfs scripts\vfs\deep.zip ^
    --script scripts\start_all_commands.emu --no-gui
```

Фрагмент вывода:

```
[debug] vfs    = scripts\vfs\deep.zip
[debug] script = scripts\start_all_commands.emu
[debug] no_gui = True
$ cd /a/b/c
$ ls
d
file1.txt
$ cp file1.txt copy.txt
$ ls
copy.txt
d
file1.txt
$ head copy.txt
deep one
$ cp /a/b/c/file1.txt /nope/dir
Error: no such directory: /nope/dir
[script] total=38 executed=37 failed=14 exited=True
```

### Ошибка загрузки VFS

```
$ python -m src.main --vfs missing.zip
[debug] vfs    = missing.zip
[debug] script = None
[debug] no_gui = False
Error: VFS file not found: missing.zip
```

Окно не открывается — эмулятор сообщает об ошибке и завершается.

### Генерация тестовых VFS-архивов

```cmd
python scripts\make_vfs.py
```

Создаёт `scripts/vfs/minimal.zip`, `several.zip`, `deep.zip`.

### Готовые скрипты ОС

В папке `scripts/` лежат `.bat` и `.sh`:

- `run_vfs_minimal.bat` — запуск с минимальным VFS.
- `run_vfs_several.bat` — запуск с VFS из нескольких файлов.
- `run_vfs_deep.bat` — запуск с глубоко вложенным VFS.
- `run_vfs_all.bat` — все команды этапов 1–5 с VFS (консоль).
- `.sh`-аналоги — для Unix-подобных систем.

Подробнее — в `scripts/README.md`.
